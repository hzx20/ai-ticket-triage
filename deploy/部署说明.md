```bash
cd /opt/continew
```

## 四、五个必须知道的坑（都是实测踩出来的）

### 1. 前端 RSA 公钥是硬编码的，必须和后端私钥配对

`continew-admin-ui/src/utils/encrypt.ts` 里写死了公钥，登录时用它加密密码，后端用 `FIELD_ENCRYPT_PRIVATE_KEY` 解密。

项目自带的是 **512 位演示公钥**。如果只换后端密钥不换前端，登录会报「密码解密失败」。

本项目的做法：重新生成 2048 位密钥对，公钥写进 `encrypt.ts`，私钥写进服务器 `.env` 的 `FIELD_ENCRYPT_PRIVATE_KEY`。**两边必须同时改**。

本地保留 `deploy/field_pub.b64` 供以后重新打包时核对；私钥只存在服务器 `/opt/continew/.env`。

### 2. 生产配置的 JustAuth 开关是死的

`application-prod.yml` 里 `continew-starter.justauth.enabled` 默认 `false`，但 `SocialLoginHandler` 构造器强制依赖 `AuthRequestFactory` Bean。关掉就启动失败：

```
No qualifying bean of type 'top.continew.starter.auth.justauth.AuthRequestFactory'
```

所以 `JUSTAUTH_ENABLED` 必须设成 `true`。不配 client-id 也没关系，只是第三方登录按钮点了没反应。

### 3. 没有 HTTPS 时的 Cookie 降级

`application-prod.yml` 里 `cookie-secure: true` + `cookie-name: __Host-refresh_token`。这两项都要求 HTTPS，纯 HTTP 部署会导致：

- `Secure` Cookie 被浏览器直接丢弃 → 登录成功后刷新页面就掉线
- `__Host-` 前缀按规范强制要求 Secure，HTTP 下同样不生效

在 compose 的 command 里显式覆盖：

```yaml
- "--application.url=http://134.175.137.18"
- "--continew-starter.refresh-token.cookie-secure=false"
- "--continew-starter.refresh-token.cookie-name=refresh_token"
```

**这是全站唯一的降级点。** 以后买了域名配好证书，把这三行删掉即可恢复标准生产配置。

### 4. 接口文档在生产环境是「自屏蔽」的，且报错信息误导

`application-prod.yml` 里有这么一行：

```yaml
nextdoc4j:
  production: ${application.production}
```

`application.production` 为 `true` 时，nextdoc4j 会屏蔽自己的所有端点。屏蔽时抛的是通用异常，被全局异常处理器包成：

```json
{"code":"1","msg":"服务器异常，请联系管理员"}
```

这个返回极易被误判成「Sa-Token 鉴权把请求拦了」，然后去改白名单——改了也没用，因为问题根本不在鉴权。

要让文档在公网可访问，两件事缺一不可：

1. `docker-compose.yml` 的 command 里加 `--nextdoc4j.production=false`
2. 生产配置的 `sa-token.extension.security.excludes` 里放行 `/doc.html`、`/nextdoc4j/**`、`/*/api-docs/**`、`/webjars/**`、`/swagger-ui/**`、`/swagger-resources/**`

只做第 1 件，页面仍然加载不出数据；只做第 2 件，返回的还是「服务器异常」。放开的只是文档，业务接口照样要 token（实测未带 token 返回 401）。

### 5. nginx 的正则 location 会抢走 `/api/` 下的静态资源

原来的配置是 `location /api/ { proxy_pass ... }`，上面还有一条对所有静态文件生效的正则：

```nginx
location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?|ttf|eot)$ { try_files $uri =404; }
```

nginx 的匹配顺序是「精确 → `^~` 前缀 → 正则 → 普通前缀」，**正则优先于普通前缀**。所以 `/api/nextdoc/_app.config.js` 会被那条正则抓走，去 `/usr/share/nginx/html/api/nextdoc/` 下找文件，找不到返回 404 —— 表现是文档页面能打开但一片空白，Network 里 JS 全是 404。

修法是给前缀加 `^~`，命中后跳过后面的正则检查：

```nginx
location ^~ /api/ { proxy_pass http://continew-backend/; ... }
```

改完不用重启容器，`docker compose exec continew-web nginx -s reload` 即可。

## 六、密钥清单（值在服务器 `/opt/continew/.env`）

| 变量 | 用途 |
| --- | --- |
| `DB_PWD` | MySQL root 密码，同时用于容器健康检查 |
| `REDIS_PWD` | Redis 密码 |
| `ACCESS_TOKEN_JWT_SECRET` | 访问令牌签名密钥（64 位十六进制） |
| `REFRESH_TOKEN_SECRET` | 刷新令牌签名密钥，必须与上一个不同 |
| `FIELD_ENCRYPT_PASSWORD` | 字段加密的 AES-256 密钥（32 位） |
| `FIELD_ENCRYPT_PUBLIC_KEY` | RSA 公钥（Base64 SPKI），与前端一致 |
| `FIELD_ENCRYPT_PRIVATE_KEY` | RSA 私钥（Base64 PKCS#8） |
| `PUBLIC_URL` | 站点地址，用于跨域与 Cookie 白名单 |

全部由 `openssl rand` 现场生成，没有默认值。
